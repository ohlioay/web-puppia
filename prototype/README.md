# Prototype — 홈 + Soft Harness® 시그니처 페이지

`docs/research/03-strategy.md`의 스크롤 시나리오와 `docs/research/06-home-and-brand-architecture.md`의
홈·내비게이션·브랜드 아키텍처를 실제로 움직이는 코드로 옮긴 검증용 프로토타입.

```
prototype/index.html    단일 파일. 빌드 불필요. 브라우저에서 바로 열면 동작.
```

## 두 개의 뷰

해시 라우터로 한 파일 안에서 두 페이지가 동작한다. 브라우저 뒤로가기도 정상 작동한다.

| 경로 | 페이지 |
|---|---|
| `#/` | **홈** — 시즌 캠페인 슬롯 + The Standard + 4브랜드 그리드 |
| `#/soft-harness` | **시그니처 페이지** — 스크롤 서사 7씬 |
| `#/shop` | **제품 목록** — 카테고리 · 브랜드 필터 + 정렬 |
| `#/shop?c=walk&b=olchi` | 필터가 URL에 실린다. 공유·북마크·광고 랜딩 가능 |
| `#/product/{id}` | **제품 상세** — 컬러웨이 · 사이즈 · 스펙 · 관련 제품 |
| `#/catalog` | **시즌 라인시트 웹북** — 페이지 넘김, 시즌 셀렉터 |
| `#/partners` | **파트너 포털** — 라인시트 · 매트릭스 발주 · 주문 이력 · 브랜드 자산 |
| `#/admin` | **관리자 콘솔** — 배너 · 상품 · 카탈로그 · 회원 · 주문 · 문의 |

## 내비게이션

2단 구조. 유틸리티 바(Brands · Where to buy · Support · EN/USD · Partner Login) + 메인 내비.
메인 내비는 `◉ Soft Harness® │ Walk  Apparel  Living  Acc  Catalog`.
**Soft Harness®만 제품 라인 이름이고 나머지는 카테고리** — 이 비대칭이 의도된 전략이며,
씰 마크와 세로 구분선으로 시각적으로 명시한다.

카테고리 호버 시 메가메뉴가 열린다: 서브카테고리 / 브랜드별 바로가기 / 이번 시즌 이미지 3열.

### 좁은 화면 (< 1000px)

메가메뉴가 있는 가로 내비는 좁은 화면에서 성립하지 않으므로 **햄버거 + 좌측 드로어**로 대체한다.
카테고리를 숨기는 대신 **전부 담는다** — 시그니처, 카테고리 5개(각각 서브카테고리 + 브랜드별 바로가기로 펼침),
Brands / Where to buy / Support, 로케일, 파트너 진입.

- 700px 미만에서는 헤더의 `PARTNER` 알약을 숨긴다 (드로어 하단에 있다)
- 링크를 누르면 드로어가 자동으로 닫힌다
- 360 / 390 / 834 / 1024 / 1440px에서 **모든 라우트에 대해 내비 도달 가능**을 자동 검증한다

## 브랜드 시스템

로고를 나열하지 않는다. 같은 서체·같은 크기의 라벨 + 점 하나로 구분한다.

| 브랜드 | 도트 | 성격 |
|---|---|---|
| PUPPIA | `#E13B26` 레드 | Since 2002 · 기능·기본기 |
| OLCHI | `#EDB230` 옐로우 | Since 2016 · 컬러풀 캐주얼 |
| PINKAHOLIC | `#B8446B` 로즈 | Since 2006 · 프리미엄 패션 |
| CATSPIA | `#3E7C74` 틸 | Since 2010 · 고양이 전용 |

**네 브랜드는 화면에서 동등하게 다룬다.** 신상 공급 능력의 차이는 브랜드를 등급으로 나눠서가 아니라
**슬롯의 개수와 성격으로** 푼다 — 시즌 슬롯의 순환 대상만 `season: true` 플래그로 데이터 레벨에서 제한하고,
화면에는 아무 표시도 하지 않는다. 세 번째 This Week 카드는 카탈로그 고정 슬롯이라 시즌마다 채울 필요가 없다.

브랜드 사정이 바뀌면 플래그 하나만 켜고 끄면 된다. 디자인 변경이 필요 없다.

## 컬러웨이

메인은 살짝 오렌지가 도는 레드. 서브는 아이보리 · 옐로우 · 블루.

| 토큰 | 값 | 역할 |
|---|---|---|
| `--red` | `#E13B26` | **브랜드 메인.** 고정 헤더 · 푸터 · CATEGORIES 섹션 · CTA · 씰 · NEW 라벨 |
| `--bone` | `#FFFFFF` | 기본 지면 (화이트) |
| `--ink` | `#17161A` | 다이어그램 가독성이 필요한 THE STANDARD 한 곳만 |
| `--blue` | `#1B4FD8` | **기술 색 전용** — 압력 분산 · 사이즈 데이터 |
| `--yellow` | `#EDB230` | 스크롤 진행바 · 장바구니 배지 · OLCHI |

### 그라운드 배치

```
HEADER      RED        ← 상시 고정
H1 Season   WHITE      (히어로 슬롯은 브랜드 컬러 블록)
H2 Standard INK        ← 유일한 어두운 섹션. 압력 다이어그램 대비 확보용
H3 Shop     WHITE
H4 Categories RED      ← 본문 안의 큰 레드 블록
H5 Houses   WHITE
H6 Fit      OFF-WHITE  (--bone2 #F4F4F1)
H7 Distribution WHITE  (도트맵을 레드로)
FOOTER      RED
CATALOG     DEEP RED   (책 스테이지)
```

지면은 순백(`--bone`)이고, 카드 썸네일·테이블 헤더·입력 필드처럼 **한 단계 눌러야 하는 면**만
`--bone2` (#F4F4F1)를 쓴다. 레드가 강한 브랜드라 지면을 채색하면 화면이 무거워진다.

텍스트를 제외한 그래픽에서 블랙은 H2 한 곳으로 제한했다. 나머지 어두운 면은 전부 레드 계열로 대체.

블루는 CTA에 쓰지 않는다. 압력 다이어그램에서 레드(목줄의 압박) ↔ 블루(하네스의 분산)로 쓰여
**제품의 논리를 그대로 색으로 설명하는 역할**이기 때문이다.

## 검색 · 장바구니 · 파트너 로그인

| 기능 | 동작 |
|---|---|
| **검색** | 헤더에서 상단 패널이 내려온다. 제품명·브랜드·카테고리·설명을 실시간 검색, 추천어 칩, 결과 없음 상태, `Esc`로 닫기 |
| **장바구니** | 우측 드로어. 제품 상세에서 담으면 실제로 적재되고, 컬러웨이·사이즈별로 라인이 분리된다. 수량 증감·삭제·합계, 헤더 아이콘에 배지 |
| **파트너 로그인** | 모달. 승인제 운영을 명시하고, 미승인 이메일로 로그인하면 심사 안내로 응답한다 |

세 오버레이 모두 배경 클릭 · `Esc` · Close 버튼으로 닫히고, 열려 있는 동안 본문 스크롤이 잠긴다.

### 세션은 사이트를 둘러보는 동안 유지된다

한 번 로그인하면 포털을 벗어나 홈·목록·상세를 돌아다녀도 로그인 상태가 그대로다.
브라우저를 새로 고쳐도 유지된다 (`localStorage`, 키 `puppia.partner.v1`).

- 세션과 함께 **작성 중인 발주서 · 주문 이력 · 메시지 스레드**가 같이 저장된다.
  매트릭스에 수백 개를 찍다가 실수로 탭을 닫아도 숫자가 남아 있다
- 로그인 상태에서는 헤더 알약이 `PARTNER` → `PORTAL`, 유틸리티 링크가
  `Partner login` → `Partner portal`로 바뀌고, 누르면 **로그인 모달 없이 곧장 `#/partners`로 간다**
- Sign out은 세션 · 발주서 · 저장소를 한 번에 비운다
- `localStorage`가 막힌 환경(프라이빗 모드 등)에서도 읽기·쓰기를 모두 `try/catch`로 감싸
  저장만 실패하고 화면은 정상 동작한다

## 제품 목록 (`#/shop`) · 제품 상세 (`#/product/{id}`)

내비게이션의 `Walk / Apparel / Living / Acc`를 누르면 홈 섹션으로 스크롤하지 않고
**전용 목록 페이지가 해당 필터가 걸린 상태로 열린다.**

- 필터가 URL에 실린다 (`#/shop?c=walk&b=olchi`) → 공유·북마크·광고 랜딩 가능
- 데스크톱은 좌측 스티키 필터 레일 + 재고 수량, 모바일은 상단 칩
- 정렬: 신상순 · 가격 낮은순 · 가격 높은순
- **필터 UI는 목록 페이지에만 둔다.** 홈은 큐레이션(신상 8개 프리뷰)만 맡는다

제품 상세는 컬러웨이 선택 시 이미지 색이 실시간으로 바뀌고, **고른 사이즈가 아래 사이즈 차트에서
하이라이트된다** — 이 카테고리의 반품 사유 1위가 사이즈이기 때문이다.
사이즈 차트는 **기본으로 열려 있고** 사이즈를 바꿔도 닫히지 않는다. 사용자가 직접 접으면 그 상태를 존중한다.
소프트하네스 제품에는 THE STANDARD 씰이 이미지 위에 붙는다.

## 파트너 포털 (`#/partners`)

### 데모 계정

```
buyer@demo-partner.com
puppia2026
→ Hundwerk GmbH · Germany
```

게이트 화면과 로그인 모달 양쪽에 표시되며, 모달의 **Use the demo account** 버튼이 폼을 자동으로 채운다.

### 매트릭스는 두 곳에 있다

라인시트에서만 발주할 수 있으면 스타일 하나를 자세히 보다가 목록으로 되돌아가야 한다.
그래서 **제품 상세 안에도 같은 매트릭스**를 띄웠고, 두 화면은 같은 주문 상태를 본다.

- 상세에서 찍은 수량이 라인시트에 그대로 보이고, 반대도 마찬가지
- 헤더의 **장바구니 = 현재 작성 중인 발주서**. 파트너 로그인 시에만 보인다
- 비로그인 상세 페이지는 `Trade only` 안내 + **`Partner login` 버튼 하나뿐**이다.
  일반 소비자용 `Where to buy` 출구를 두지 않는다 — **이 사이트에서는 아무도 소매로 살 수 없다**
- 장바구니 드로어에서도 SKU별 수량을 바로 조정할 수 있다

### 매트릭스 발주

바이어는 SKU당 1개가 아니라 수십 개씩 산다. B2C의 "컬러 고르고 → 사이즈 고르고 → 담기"를 반복시키면
한 스타일에 20번 클릭해야 한다. 그래서 **표 하나에 숫자를 찍는 방식**으로 만들었다.

- **행 = 사이즈, 열 = 컬러웨이.** 행·열·라인 합계가 입력 즉시 갱신
- 셀마다 **가용 재고(avl)** 표시. 재고 0인 셀은 입력 불가(`—`)
- 재고 초과는 차단이 아니라 **앰버 경고** — 선주문 의사를 막지 않는다
- `↑` `↓` `Enter`로 같은 열의 위아래 이동, 포커스 시 값 전체 선택
- 하단 **고정 합계 바**: 유닛 · 스타일 수 · 주문 금액 · MOQ 진척도
- **MOQ 미달 시 검토는 열리고 제출만 잠긴다.** 얼마가 모자란지 보여주는 편이 막는 것보다 낫다
- 제출 → PO 번호 발급 → Orders 탭에 즉시 반영

### 스타일 자산 (Assets)

바이어는 제품을 받기 전에 **자기 채널에 올릴 사진**부터 필요하다. 그래서 발주 동선 안에 자산을 넣었다.

- 제품 상세(로그인 상태)의 두 번째 버튼이 **Assets**다. 기존 `Find my size` 자리를 대체한다
  — 사이즈는 아래 사이즈 차트가 이미 열린 채로 답하고 있으므로 중복이었다
- 상품 등록 시 스타일마다 **구글 드라이브 폴더 링크**를 하나 걸어둔다 (데이터의 `as` 필드).
  버튼을 누르면 링크·복사 버튼·폴더 구성(사진 / 스와치 / 스펙시트 / 케어라벨)이 시트로 뜬다
- 링크가 비어 있는 스타일은 `Not linked yet`으로 표시하고 열기를 막는다

### 주문 단위 일괄 수집

주문 상세의 **Assets for this order**는 그 PO에 들어간 **모든 스타일의 폴더를 한 화면에 모은다.**
스타일 5개짜리 주문이면 상세 페이지 5곳을 돌 필요가 없다.

- 스타일별 Copy / Open
- **Copy all links** — 스튜디오에 한 번에 붙여넣을 수 있는 목록
- **Download link list (CSV)** — 브랜드 · 스타일 · 코드 · 폴더 링크 4열.
  라인시트 내보내기와 같은 저장 경로(`downloads` capability → 앵커 폴백)를 쓴다

> 프로토타입의 링크는 플레이스홀더다. 시트 상단에 그 사실을 명시해 실제 운영과 혼동되지 않게 했다.

### 탭 구성

| 탭 | 경로 | 내용 |
|---|---|---|
| Line sheet | `#/partners` | 도매가 · MSRP · 마진 + 매트릭스 그리드. 브랜드/카테고리 필터 |
| Orders | `#/partners/orders` | 주문 이력, 상태 배지, **View**로 상세 진입 |
| Messages | `#/partners/messages` | 주문에 연결되는 메시지 스레드 (미읽음 배지) |
| 주문 상세 | `#/partners/orders/{PO}` | 메타 · 진행 단계 · 사이즈/컬러 브레이크다운 · 재주문 복제 · 자산 일괄 수집 |
| Brand assets | `#/partners/assets` | 사진 · 스펙시트 · 로고 · 인증서 목록 |

주문 상세는 URL에 PO 번호가 들어가므로 메일이나 메신저로 그대로 공유된다.
재주문 버튼을 목록이 아니라 상세에 둔 이유는, 바이어가 재주문 전에 무엇을 얼마나 샀는지 먼저 확인하기 때문이다.

### 메시지 스레드

이메일로 흩어지면 "어느 선적 얘기였지"를 매번 되짚어야 하므로, 스레드를 **PO 번호에 연결**한다.

- 탭 미읽음 배지 + 목록의 점, 스레드를 열면 즉시 해제
- 좌우 말풍선, `Ctrl + Enter` 전송
- 새 메시지: 제목 + 연결할 주문 선택 + 본문 (모달 `prompt()` 대신 인라인 폼 — 샌드박스에서 차단되지 않는다)
- 주문 상세의 **Message us about this order** → 해당 PO 스레드로, 없으면 PO가 채워진 새 스레드

회신 시간은 약속하지 않고 "보통 1영업일 내"처럼 관측된 사실만 적는다.

### 라인시트 내보내기

바이어는 받은 라인시트를 사내 결재와 자체 시스템 업로드에 쓴다.

| 옵션 | 값 |
|---|---|
| 범위 | 라인시트(현재 필터) / 현재 작성 중인 주문만 |
| 형식 | CSV (UTF-8 BOM) / Excel `.xls` (SpreadsheetML, 헤더 볼드) |
| 컬럼 | 브랜드 · 스타일 · 코드 · 카테고리 · 사이즈 · 컬러웨이 · SKU · 도매가 · MSRP · 가용재고 · 주문수량 · 라인금액 |
| 행 | **SKU 1개당 1행** — 사이즈 × 컬러가 전부 펼쳐진다 |

내보내기 창은 실제 생성될 내용의 **미리보기**와 행 수·파일명을 함께 보여준다.
장바구니 드로어의 **Export order**로도 주문만 바로 내보낼 수 있다.

**다운로드는 두 경로를 모두 지원한다.**

| 환경 | 동작 |
|---|---|
| 실제 서버 / 파일 직접 열기 | `Blob` + `<a download>` 로 바로 저장 |
| 아티팩트 뷰어 | `downloads` 런타임 기능(`claude.use('downloads')`)으로 저장. 뷰어가 파일명·용량 확인을 띄운다 |

뷰어에서 확장자가 거부되면(`extension_not_enabled`) CSV는 `.txt`로 자동 재시도하고
"`.csv`로 이름을 바꾸면 엑셀에서 열립니다"라고 안내한다. 사용자가 저장을 거절하면 **아무 메시지도 띄우지 않는다**
— 본인이 누른 취소에 오류를 보여줄 이유가 없다. 어느 경로도 불가능할 때를 위해 **클립보드 복사**를 항상 함께 둔다.

### 화폐

기본 표시는 **USD**. 해외 바이어가 주 사용자이고 MOQ(USD 3,000)와 인코텀즈도 달러 기준이다.

## 관리자 콘솔 (`#/admin`)

사이트에 나가는 모든 것을 한 곳에서 관리한다. 전제는 하나 — **쓰는 사람이 입사 첫 주일 수도 있다.**
자세한 설계 근거는 [`docs/research/07-admin-console.md`](../docs/research/07-admin-console.md).

```
admin@puppia.com
puppia-admin
```

푸터 우측의 **Staff console** 링크 또는 주소창의 `#/admin`으로 들어간다.
콘솔에서는 마케팅 헤더·푸터·진행 바가 **전부 사라진다** — 사이트의 한 페이지가 아니라 별개의 도구다.

| 그룹 | 메뉴 | 하는 일 |
|---|---|---|
| Every day | Overview | 오늘 처리할 일, 지표 4개, 최근 주문 |
| Content | Home screen | 시즌 히어로 · This Week 3칸 · 잠긴 섹션 |
| Content | Products | 목록 · 검색 · 등록 · 수정 · 삭제 |
| Content | Catalog | 시즌 웹북 표지 · 공개 여부 |
| Buyers | Orders | 주문 목록 · 상태 변경 · 브레이크다운 |
| Buyers | Buyer accounts | 승인 대기 · 활성 · 정지 |
| Buyers | Enquiries | 문의 스레드 · 답변 |
| Setup | Settings | 브랜드 · 카테고리 · 컬러웨이 · 사이즈표 |

사이드바에 **처리 대기 건수 배지**가 붙는다. 좁은 화면에서는 가로 스크롤 탭 스트립으로 바뀐다.

### 신입도 쓸 수 있게 만든 다섯 가지

1. **데이터 사본이 없다.** 콘솔은 사이트가 읽는 바로 그 객체에 쓴다.
   상품 하나를 고치면 목록·상세·검색·라인시트·매트릭스·주문서가 동시에 바뀐다
2. **슬롯을 채우게 하고 배치는 못 건드리게 한다.** 홈 편집은 페이지 빌더가 아니라 정해진 칸이다 —
   **콘솔에서 한 편집이 레이아웃을 깨뜨릴 방법이 없다**
3. **잠긴 것은 잠긴 채로 보여준다.** THE STANDARD는 잠금 카드로 등장하고 왜 잠겼는지를 그 자리에서 설명한다.
   숨기면 신입이 헤매고, 열어두면 브랜드의 근거가 지워진다
4. **모든 필드가 "이걸 바꾸면 어디가 바뀌는지" 말한다.** 라벨만 있는 폼은 아무것도 알려주지 않는다
5. **저장과 게시를 구분한다.** 홈 편집은 하단 미게시 바에서 Publish를 눌러야 방문자에게 나간다

### 상품 등록 — 체크리스트가 게이트다

공개 조건 5개(이름 / MSRP>0 / 컬러웨이 / 설명 40자 / 드라이브 링크)가 실시간 체크리스트로 붙는다.
하나라도 비면 공개 스위치가 잠기고, 무엇이 남았는지 알려준다. 미완성이어도 **숨김 초안으로 저장은 된다.**

타이핑 중에는 체크리스트만 다시 그린다. 폼을 통째로 다시 그리면 커서가 단어 중간에서 날아간다.

### 콘솔에서 한 일이 사이트에 닿는다

| 콘솔 | 사이트 |
|---|---|
| 홈 히어로 변경 → Publish | `#/` 첫 화면이 바뀐다 |
| 상품 등록 + 공개 ON | `#/shop`·검색·라인시트·매트릭스에 동시 등장 |
| 공개 OFF | 매장에서 사라진다. 과거 주문 기록은 그대로 |
| 대기 바이어 승인 | 그 계정으로 로그인이 뚫린다 |
| 계정 정지 | 로그인 차단 + 접속 중이던 세션도 끊긴다 |
| 주문 상태 변경 | 바이어 포털의 배지가 바뀐다 |
| 문의 답변 | 바이어 포털 스레드에 도착한다 |

로그인 검증이 데모 계정 하드코딩에서 **계정 목록 조회**로 바뀌었기 때문에,
콘솔의 승인·정지가 실제로 의미를 갖는다.

> **실 구축 시 다르게 할 것**: 프로토타입은 `localStorage`(`puppia.admin.v1`)에 상태를 담는다.
> 실제로는 HttpOnly 세션 쿠키 + 서버 검증, **역할 분리**(상품은 고치되 승인은 못 하는 MD),
> MariaDB, 감사 로그, 소프트 삭제가 필요하다.

## 카탈로그 웹북 (`#/catalog`)

시즌 PDF 라인시트를 페이지가 넘어가는 웹북으로 보여준다. PDF 뷰어를 임베드하지 않는다.

- 2페이지 스프레드 · 3D 페이지 넘김 (`rotateY` + `backface-visibility`)
- 좌우 클릭 · `←` `→` 키 · 버튼 세 가지 조작
- 시즌 셀렉터(SS26 / FW25 / SS25) — 이전 시즌이 아카이브로 남는다
- 라인시트 페이지는 **스타일 × 컬러웨이** 단위로 진열 (실제 라인시트와 발주 단위가 그렇다)
- PDF 원본 다운로드는 파트너 로그인 후

## 목적

이 파일은 **디자인 시안이 아니라 스크롤 연출·인터랙션의 타당성 검증용**이다.
확인하려는 것은 세 가지다.

1. 스크롤 한 번으로 "왜 소프트하네스인가"가 설명되는가
2. 3D 없이 어디까지 갈 수 있는가 (성능 예산 검증)
3. 핏 시뮬레이터 같은 인터랙션이 실제로 이해되는가

**모든 도형은 플레이스홀더다.** 제품 사진·3D 모델·화보가 들어갈 자리를 SVG 라인아트로 대신 채웠다.
실제 자산으로 교체할 때 레이아웃과 스크롤 타이밍은 그대로 재사용할 수 있다.

## 기술 메모

- **외부 라이브러리 0개.** GSAP·Lenis·Three.js 없이 바닐라 JS + `requestAnimationFrame` 스로틀 스크롤로 구현했다.
  실제 구축 시 GSAP ScrollTrigger를 쓰면 코드가 짧아지지만, **이 정도 연출은 라이브러리 없이도 가능하다**는 것이 확인됐다.
- **핀 방식**: `.scene { height: N vh }` + `.pin { position: sticky }`. 스크롤 잭 없이 네이티브 스크롤을 유지한다.
- **씬 진행률**은 `--p` CSS 변수(0→1)로 내려보내고, CSS `calc()`와 JS가 각각 필요한 만큼만 읽는다.
- **컬러웨이**는 `--product` 변수 하나만 바꾼다. 실제 사이트에서 3D 머티리얼 교체로 대체될 지점.
- **`prefers-reduced-motion: reduce`** 시 모든 핀이 해제되고 각 씬이 최종 상태의 정적 레이아웃으로 렌더된다
  (문서 길이 12,284px → 7,334px). 정보 손실 없음.
- **해시 라우터**: `#/` 로 시작하면 라우트, 그 외 `#id`는 인페이지 앵커. 뷰 전환 시 스크롤을 리셋하고
  숨겨진 뷰의 씬은 `offsetParent === null` 로 걸러 스크롤 계산에서 제외한다.
- 390 / 834 / 1440px에서 가로 오버플로 0, 콘솔 에러 0으로 확인.
