# 06. 메인 홈 · 내비게이션 · 브랜드 아키텍처

## 1. 문제의 정확한 진술

같은 자리를 세 가지가 동시에 원한다.

| | 성격 | 주기 |
|---|---|---|
| **시즌 배너 / 신상** | 상업적, 브랜드 혼재, 매주 갈림 | 회전 |
| **소프트하네스 전문성** | 브랜드를 신뢰할 유일한 근거 | 영구 |
| **4개 브랜드** | 그중 **둘은 신상이 더 이상 나오지 않음** | 상시 |

일반적인 국내 몰 홈(배너 캐러셀 → 신상 그리드 → 카테고리)은 1번만 만족시키고, 2번을 파괴하고, 3번을 로고 나열로 때운다.

그리고 3번에는 함정이 하나 더 있다. **네 브랜드의 콘텐츠 공급 능력이 서로 다르다.**

| 브랜드 | 신상 공급 | 홈에서의 역할 |
|---|---|---|
| PUPPIA | 매 시즌 | 시즌 슬롯 순환 대상 |
| OLCHI | 매 시즌 | 시즌 슬롯 순환 대상 |
| PINKAHOLIC | **종료** | 아카이브 |
| CATSPIA | **종료** | 아카이브 |

네 브랜드에 균등하게 슬롯을 주면 **둘은 매 시즌 비는 자리**가 된다.
죽은 공간은 브랜드를 낡아 보이게 하고, 운영자에게는 채울 수 없는 숙제를 남긴다.

---

## 2. 해법의 원리 — 두 개의 시계

홈은 **두 개의 시계**로 돌아간다.

- **THE STANDARD (고정 시계)** — 절대 안 바뀐다. 소프트하네스. 위치가 구조적으로 보장된다.
- **THE SEASON (회전 시계)** — CMS 슬롯. 배너·신상·캠페인이 매주 갈린다.

> **핵심은 둘을 섞지 않고 번갈아 놓는 것이다.**
> 배너 안에 하네스를 우겨넣으면 배너가 죽고, 하네스 섹션에 신상을 섞으면 전문성이 죽는다.
> 전문성은 "설명"이 아니라 **위치가 절대 안 바뀐다는 사실 자체**로 증명된다.

애플이 아이폰을 홈 1번 타일에 20년째 두는 것과 같은 원리다. 캠페인은 그 아래 타일에서 매주 갈린다.

## 3. 홈 구조 — 7개 스크린

```
S1  THE SEASON      시즌 캠페인 히어로 (CMS 슬롯) + This Week 스트립
S2  THE STANDARD    소프트하네스. 고정. 압력 스토리 압축판 → /soft-harness
S3  SHOP            브랜드 탭 × 카테고리 칩 × 제품 그리드 (신상 우선)
S4  CATEGORIES      Walk / Apparel / Living / Acc — 4개 도어
S5  THE HOUSES      4개 브랜드 블록
S6  FIT FINDER      사이즈 추천 CTA
S7  GLOBAL          유통 국가 + 바이어 진입
```

**S1 → S2가 연달아 붙는 것이 설계의 전부다.** 스크롤 한 번에 "이번 시즌 무엇이 새로 나왔나"와 "이 브랜드가 누구인가"가 순서대로 나온다.

### 캐러셀을 쓰지 않는 이유

배너 캐러셀은 2번째 슬라이드부터 조회율이 급락한다. 대신:

- S1은 **단일 히어로 1개** (이번 시즌 주력)
- 그 바로 아래 얇은 **"This Week" 스트립** 3칸

→ 모든 배너가 동시에 보이고, 클릭하지 않아도 이번 시즌 라인업이 한눈에 들어온다.

### 슬롯 개수는 콘텐츠 공급 능력에 맞춘다

이게 죽은 공간을 막는 실제 장치다.

| 슬롯 | 성격 | 채우는 주기 | 대상 |
|---|---|---|---|
| `season.hero` × 1 | 회전 | 시즌마다 | **PUPPIA · OLCHI만** |
| `season.week` × 2 | 회전 | 시즌마다 | **PUPPIA · OLCHI만** |
| `evergreen` × 1 | 고정 | 카탈로그 발행 시 (연 2회) | 전 브랜드 공통 — 시즌 카탈로그 웹북 |

**운영자가 매 시즌 채워야 할 칸은 세 개뿐이고, 전부 신상이 실제로 나오는 브랜드다.**
세 번째 카드는 카탈로그로 고정해서 비지 않게 만든다. 아카이브 브랜드는 여기에 등장하지 않는다.

### CMS 슬롯 정의 (개발 시 그대로 구현)

| 슬롯 | 개수 | 필드 |
|---|---|---|
| `season.hero` | 1 | 이미지/영상, 브랜드(PUPPIA·OLCHI), 아이브로우, 헤드라인, 링크 |
| `season.week` | 2 | 이미지, 브랜드(PUPPIA·OLCHI), 라벨, 링크 |
| `evergreen` | 1 | **고정 — 시즌 카탈로그 웹북으로 연결. 시즌마다 손대지 않음** |
| `shop.pinned` | 0–4 | 그리드 상단 고정 제품 |

**S2는 CMS 슬롯이 아니다.** 하드코딩한다. 운영자가 실수로 지울 수 없어야 한다.

## 4. 내비게이션 — 2단 구조

```
[유틸리티]  Brands     Where to buy     Support          EN / KRW     Partner Login
[메인]      PUPPIA   ◉ Soft Harness®  │  Walk   Apparel   Living   Acc   Catalog      [검색] [장바구니]
```

### Soft Harness®의 비대칭을 살린다

사용자가 제안한 구성에는 의도적인 비대칭이 있다 — **나머지는 전부 카테고리인데 이것만 제품 라인 이름**이다.
이 비대칭이 곧 전략이다. 애플 내비에 "노트북"이 아니라 "MacBook"이 있는 것과 같다.

시각적으로 명시한다:
- 앞에 **씰(seal) 마크** ◉ 를 붙인다
- 나머지 카테고리와 **얇은 세로 구분선**으로 분리한다
- 폰트 웨이트를 한 단계 올린다

메뉴를 보는 것만으로 "이 브랜드에는 이름 붙은 물건이 하나 있다"가 읽힌다.

### 메가메뉴 (카테고리 호버 시)

3열 구성: **서브카테고리 / 브랜드별 바로가기 / 이번 시즌 이미지 1장**

```
Walk  ▾
┌──────────────┬─────────────────┬──────────────────┐
│ Harness      │ PUPPIA          │  [시즌 이미지]    │
│ Leash        │ OLCHI           │  SS26 Walk Kit   │
│ Collar       │ PINKAHOLIC      │  자세히 보기 →    │
│ Walk Set     │ CATSPIA         │                  │
└──────────────┴─────────────────┴──────────────────┘
```

브랜드 열이 있어서 **"올치 하네스만 보고 싶다"가 두 번 클릭으로 끝난다.** 이게 4브랜드 사이트의 핵심 동선이다.

### 유틸리티 바가 필요한 이유

메인 내비가 카테고리로 꽉 차면 **Partner Login이 갈 곳이 없어진다.** 바이어 진입은 사이트의 수익 축이므로 사라지면 안 된다. 얇은 유틸리티 바를 위에 얹어 언어·통화·매장찾기·바이어 로그인을 모은다. 글로벌 브랜드 사이트의 표준 2단 구조다.

## 5. 브랜드 아키텍처 — Branded House with Endorsement

### 결정: 브랜드 로고를 나열하지 않는다

4개 로고를 그리드에 뿌리면 시각적 소음이 되고, 사이트가 "여러 브랜드를 모아 파는 편집숍"으로 읽힌다.
메인은 **퍼피아 브랜드 사이트**여야 하므로 나머지는 **라벨(label)** 로 다룬다.

| 브랜드 | 라벨 | 도트 | 성격 | 상태 |
|---|---|---|---|---|
| PUPPIA | `PUPPIA` | `#E13B26` 레드 | 2002~ · 기능·기본기 · 소프트하네스 | **Active** |
| OLCHI | `OLCHI` | `#EDB230` 옐로우 | 2016~ · 컬러풀 캐주얼 | **Active** |
| PINKAHOLIC | `PINKAHOLIC` | `#B8446B` 로즈 | 2006–2024 · 뉴욕발 프리미엄 패션 | Archive |
| CATSPIA | `CATSPIA` | `#3E7C74` 틸 | 2010–2023 · 고양이 전용 | Archive |

> 액티브 두 브랜드가 브랜드 메인 컬러(레드)와 서브 컬러(옐로우)를 가져간다.
> 아카이브 두 브랜드는 채도가 낮은 로즈·틸을 쓴다 — **컬러의 세기 자체가 위계를 말한다.**

**모든 제품 카드에 같은 서체 · 같은 크기 · 도트 색만 다르게.**

이 방식의 이득:
1. 그리드가 로고 소음 없이 **하나의 시스템**으로 읽힌다
2. 브랜드는 여전히 즉시 식별된다
3. **새 브랜드가 추가돼도 디자인 비용이 0이다** — 라벨과 도트 색만 추가

### 각 브랜드의 자리

- **홈 S5 The Houses** — Active 2 + Archive 2 로 나눈 블록 (6절 참조)
- **제품 그리드** — `NEW / PUPPIA / OLCHI / ARCHIVE` 탭으로 필터
- **메가메뉴** — 카테고리별 브랜드 바로가기
- **`/brands/olchi`** 등 브랜드별 페이지 — 자체 캠페인 화보를 걸 수 있는 공간

브랜드는 **하위 브랜드로서 노출되되 독립 사이트를 갖지 않는다.** 트래픽과 SEO를 한곳에 모으는 것이 4개로 쪼개는 것보다 압도적으로 유리하다.

## 6. 죽은 공간 방지 — Active / Archive 이원화

핑카홀릭과 캐츠피아는 더 이상 신상이 나오지 않는다. 그런데 홈과 카탈로그에서 다른 둘과 똑같이 취급하면
**시즌마다 비는 자리**가 생기고, 사이트 전체가 관리되지 않는 인상을 준다.

### 원칙

> **콘텐츠가 없는 브랜드에 콘텐츠 슬롯을 주지 않는다. 대신 그 성격에 맞는 다른 슬롯을 준다.**

신상이 없다는 건 죽었다는 뜻이 아니라 **아카이브**라는 뜻이다. 그리고 아카이브에는 신상에 없는 무기가 있다 — **희소성**.

### 세 곳에서 각각 다르게 다룬다

**① H1 시즌 슬롯 — 아예 등장시키지 않는다.**
히어로와 This Week 회전 대상은 PUPPIA·OLCHI로 한정한다. 세 번째 카드는 카탈로그 고정 슬롯이다.

**② H3 SHOP — 브랜드 탭을 4개 나열하지 않는다.**

```
[ NEW ARRIVALS ]  [ ● PUPPIA ]  [ ● OLCHI ]  [ ● ARCHIVE ]
```

- 기본 탭은 **NEW ARRIVALS** (브랜드 무관, 신상만)
- 액티브 두 브랜드만 자기 이름의 탭을 갖는다
- 아카이브 두 브랜드는 **ARCHIVE 하나로 묶는다**

빈 탭이 구조적으로 생길 수 없다. 그리고 "아카이브"라는 이름이 붙는 순간, 재고 정리가 **큐레이션**으로 읽힌다.

**③ H5 THE HOUSES — 위계를 디자인으로 인정한다.**

```
ACTIVE   — 매 시즌 신상이 나옵니다
         PUPPIA          OLCHI              (큰 카드, 흰 배경, 브랜드 컬러 바)

ARCHIVE  — 신규 시즌 종료, 재고 소진까지
         PINKAHOLIC      CATSPIA            (작은 카드, 톤다운 배경)
```

크기와 배경으로 등급 차이를 명시하면 **"왜 이 브랜드는 콘텐츠가 없지?"라는 질문 자체가 생기지 않는다.**
애초에 다른 카테고리라고 선언했기 때문이다.

### LAST STOCK 라벨

아카이브 제품에는 `NEW` 대신 **`LAST STOCK`** 라벨을 옐로우로 붙인다.

- 구매 동기가 된다 — 다시 안 나온다는 사실이 곧 이유다
- 재고 소진 시 자동으로 사라지므로 별도 운영이 필요 없다
- 바이어에게는 "잔여 재고 클리어런스" 협상 근거가 된다

> 신상이 없다는 약점을, 다시 구할 수 없다는 강점으로 뒤집는 것이 이 절의 목적이다.

## 6-1. 컬러웨이

메인은 **살짝 오렌지가 도는 레드**. 서브는 아이보리 · 옐로우 · 블루.

| 토큰 | 값 | 역할 | 화면 비중 |
|---|---|---|---|
| `--bone` 아이보리 | `#F4F0E6` | 기본 지면 | **약 60%** |
| `--ink` 잉크 | `#17161A` | 대비 섹션 지면 (H2 · H4 · 카탈로그) | 약 25% |
| `--red` 레드 | `#E13B26` | **브랜드 메인.** CTA · 씰 · 활성 상태 · NEW 라벨 · PUPPIA | 약 8% |
| `--blue` 블루 | `#1B4FD8` | 기술·정보 요소 전용 (압력 분산 · 사이즈 · 데이터) | 약 5% |
| `--yellow` 옐로우 | `#EDB230` | LAST STOCK · ARCHIVE 표시 · OLCHI | 약 2% |

**핵심 규칙 두 가지.**

1. **레드는 넓게 칠하지 않는다.** 히어로 슬롯 하나와 작은 요소들에만 쓴다. 면적이 좁을수록 강해진다.
2. **블루는 브랜드 색이 아니라 기술 색이다.** 압력 분산 다이어그램에서 레드(목줄의 압박) ↔ 블루(하네스의 분산)로 쓰이며,
   이 대비가 제품의 논리를 그대로 색으로 설명한다. 그래서 블루를 CTA에 쓰지 않는다.

## 7. 추가 장치 — THE STANDARD 씰

소프트하네스가 등록상표(®)라는 사실을 자산으로 쓴다.

원형 씰 마크를 하나 만들어 **다음 모든 곳에 동일하게** 붙인다:

- 내비게이션의 `Soft Harness®` 앞
- 소프트하네스 제품 카드 전부
- 홈 S2
- 제품 상세 페이지
- **실제 제품 행택(hangtag)**

효과는 인텔의 "Intel Inside"와 같다. 4개 브랜드 · 수백 SKU가 섞인 카탈로그 안에서 **시그니처가 항상 식별된다.** 그리고 온라인의 기호가 오프라인 택에도 있으면, 매장에서 제품을 만진 사람이 사이트에서 같은 기호를 다시 만난다.

제작비는 사실상 0이고, 브랜드 자산 가치는 크다.

## 8. 페이지 역할 재정의

| 페이지 | 역할 | 성격 |
|---|---|---|
| `/` **홈** | 이번 시즌 + 브랜드 정체성 + 쇼핑 진입 | 상업적, 매주 갱신 |
| `/soft-harness` **시그니처** | 기존 스크롤 서사 페이지 그대로 | 몰입형, 거의 안 바뀜 |
| `/walk` `/apparel` `/living` `/acc` | 카테고리 리스팅 | 도구형 |
| `/catalog` **카탈로그** | 시즌 라인시트 PDF를 **웹북(페이지 넘김)** 으로 열람 | 열람형 |
| `/brands/{brand}` | 브랜드별 캠페인 | 반몰입형 |
| `/partners` | B2B 존 | 도구형 |

### `/catalog` — 시즌 라인시트 웹북

시즌마다 제작하는 PDF 라인시트를 **페이지가 넘어가는 웹북**으로 보여준다. PDF 뷰어를 임베드하지 않는다 —
모바일에서 확대·축소 지옥이 되고, 검색엔진이 읽지 못하며, 브랜드 톤과 무관한 회색 UI가 화면을 차지한다.

**구성**

| 요소 | 동작 |
|---|---|
| 시즌 셀렉터 | `SS26 / FW25 / SS25 …` 이전 시즌이 그대로 아카이브로 남는다 |
| 2페이지 스프레드 | 실제 책처럼 좌우 펼침. 표지만 단독 우측 |
| 페이지 넘김 | 3D 회전으로 넘어간다. 좌우 클릭 · `←` `→` 키 · 버튼 |
| 페이지 구성 | 표지 → 목차 → 브랜드 디바이더 → 컬러웨이 라인시트 → 사이즈 차트 → 주문·거래조건 → 뒷표지 |
| PDF 원본 | **파트너 로그인 후 다운로드.** 웹북은 공개, 원본은 승인된 바이어에게만 |

**설계 의도 세 가지**

1. **바이어의 첫 관문이 된다.** 로그인 없이 라인업 수준을 확인할 수 있으므로, 거래를 검토하는 바이어가 문의 전에 스스로 판단한다 → 문의 품질이 올라간다.
2. **일반 소비자에게는 브랜드의 깊이를 보여준다.** 시즌 카탈로그가 몇 년치 쌓여 있다는 사실 자체가 헤리티지의 증거다.
3. **홈의 고정 슬롯을 채운다.** This Week 세 번째 카드가 항상 최신 카탈로그를 가리키므로, 신상이 부족한 시즌에도 빈 칸이 생기지 않는다.

**라인시트 페이지는 컬러웨이 단위로 진열한다** — 같은 스타일을 반복 나열하지 않고 `스타일 × 컬러` 로 펼친다.
실제 라인시트가 그렇게 생겼고, 바이어가 발주 시 보는 단위도 그것이다.

기존에 만든 스크롤 프로토타입은 **버리지 않는다.** 그대로 `/soft-harness`가 된다.
홈에서 S2를 클릭하면 그 페이지로 들어간다 — 홈은 "예고편", 시그니처 페이지가 "본편"이다.

## 9. 운영 관점에서의 검증

이 구조가 실제로 굴러가는지 세 가지 시나리오로 확인한다.

**시나리오 A — 올치 신상 출시**
운영자가 `season.hero` 슬롯의 이미지와 링크를 올치 캠페인으로 교체한다. 브랜드 필드를 `OLCHI`로 두면 아이브로우에 옐로우 도트가 자동으로 붙는다. **S2는 건드리지 않는다.**

**시나리오 B — 이번 시즌 신상이 퍼피아뿐**
`season.hero`에 퍼피아를 넣고, `season.week` 두 칸도 퍼피아 품목으로 채운다. 세 번째 칸은 카탈로그 고정 슬롯이라 애초에 채울 필요가 없다. **비는 자리가 생기지 않는다.**

**시나리오 C — 핑카홀릭 재고 클리어런스**
`ARCHIVE` 탭의 해당 제품에 `LAST STOCK` 라벨이 붙는다. 시즌 슬롯을 하나도 쓰지 않고, H5 아카이브 블록과 H3 탭만으로 처리된다. **액티브 브랜드의 시즌 서사를 방해하지 않는다.**

**시나리오 D — 새 시즌 카탈로그 발행**
`/catalog`에 시즌을 하나 추가하면 시즌 셀렉터에 버튼이 늘고 이전 시즌은 그대로 아카이브로 남는다. This Week의 고정 카드 링크는 그대로 최신 시즌을 가리킨다. **연 2회만 손대면 된다.**

네 시나리오 모두 **S2를 건드리지 않고** 처리되고, **채울 수 없는 빈 슬롯이 생기지 않는다.** 그게 이 구조의 목적이다.
