# 관리자 콘솔 설계 (`/admin`)

사이트에 나가는 모든 것 — 배너, 상품, 카탈로그, 바이어 계정, 주문, 문의 — 을 한 곳에서 관리한다.
전제는 하나다. **이 콘솔을 쓰는 사람은 입사 첫 주일 수도 있다.**

---

## 1. 설계 원칙 다섯 가지

### 원칙 1 — 데이터 사본을 만들지 않는다

콘솔은 사이트가 읽는 **바로 그 객체**에 쓴다. `HOME`, `PRODUCTS`, `MEMBERS`, `SEASONS`, `ORDERS`, `THREADS`.
관리자용 사본이 따로 없으므로 "관리자에는 바뀌었는데 사이트에는 안 바뀌었다"가 구조적으로 불가능하다.

상품 하나를 고치면 목록 · 상세 · 검색 · 라인시트 · 발주 매트릭스 · 주문서가 **동시에** 바뀐다.
신입에게 "여기도 고치고 저기도 고치세요"라고 말할 일이 없다.

### 원칙 2 — 슬롯을 채우게 하고, 배치는 못 건드리게 한다

홈 화면 편집은 자유 배치 페이지 빌더가 아니라 **정해진 칸**이다.
칸의 개수와 순서는 고정이고 편집자는 내용만 넣는다.

> 결과: **콘솔에서 한 편집이 레이아웃을 깨뜨릴 방법이 없다.**
> 페이지 빌더를 줬을 때 반드시 생기는 "누가 홈을 망가뜨렸다" 사고가 원천적으로 발생하지 않는다.

### 원칙 3 — 잠긴 것은 잠긴 채로 보여준다

THE STANDARD(소프트하네스) 섹션은 홈 편집 화면에 **잠금 카드로 등장한다.** 숨기지 않는다.

- 숨기면 → 신입은 그 섹션이 어디서 오는지 몰라 헤맨다
- 편집 가능하게 하면 → 캠페인 배너를 바꾸다가 브랜드의 근거를 지운다

그래서 **보이되 잠긴** 상태로 두고, 왜 잠겼는지를 그 자리에서 설명한다.
카테고리 5개 추가, 결제 조건 스키마 변경도 같은 방식으로 처리한다.

### 원칙 4 — 모든 필드가 "이걸 바꾸면 어디가 바뀌는지" 말한다

라벨만 있는 폼은 신입에게 아무것도 알려주지 않는다. 모든 입력 아래에 한 줄이 붙는다.

| 필드 | 붙는 설명 |
|---|---|
| 상품명 | 모든 화면에 나오고 주문서에도 인쇄됩니다 |
| MSRP | 도매가는 절반으로 자동 계산됩니다 — 숫자를 두 번 입력하지 않습니다 |
| 카테고리 | 상단 메뉴와 **사이즈 체계**(XS–XL / 단일 사이즈)를 함께 결정합니다 |
| 컬러웨이 | 발주 매트릭스의 열 하나가 됩니다 |
| 드라이브 링크 | 상세페이지 Assets 버튼과 주문서 일괄 다운로드가 이 필드 하나를 읽습니다 |
| THE STANDARD 씰 | 소프트하네스 구조가 아닌 제품에 붙이는 것이 여기서 저지를 수 있는 유일한 브랜드 손실입니다 |

### 원칙 5 — 저장과 게시를 구분하고, 미게시 상태를 화면에 못 박는다

홈 편집은 고칠 때마다 즉시 반영되지 않는다. 화면 하단에 **미게시 바**가 올라온다.

```
Not published yet. 홈 화면은 방문자에게 아직 이전 버전을 보여주고 있습니다.
                                              [ Discard ]  [ Publish to the site ]
```

편집 중인 상태와 공개 중인 상태가 다르다는 사실이 항상 화면에 있다.

## 2. 화면 구성

좌측 고정 사이드바 + 상단 브레드크럼. 마케팅 사이트의 헤더 · 푸터 · 진행 바는 **완전히 제거된다** —
콘솔은 사이트의 한 페이지가 아니라 별개의 도구다.

| 그룹 | 메뉴 | 경로 | 하는 일 |
|---|---|---|---|
| Every day | **Overview** | `#/admin` | 오늘 처리할 일, 지표 4개, 최근 주문 |
| Content | **Home screen** | `#/admin/home` | 시즌 히어로 · This Week 3칸 · 잠긴 섹션 |
| Content | **Products** | `#/admin/products` | 목록 · 검색 · 필터 · 등록 · 수정 · 삭제 |
| Content | **Catalog** | `#/admin/catalog` | 시즌 웹북 표지 · 공개 여부 |
| Buyers | **Orders** | `#/admin/orders` | 주문 목록 · 상태 변경 · 브레이크다운 |
| Buyers | **Buyer accounts** | `#/admin/members` | 승인 대기 · 활성 · 정지 |
| Buyers | **Enquiries** | `#/admin/messages` | 문의 스레드 · 답변 |
| Setup | **Settings** | `#/admin/settings` | 브랜드 · 카테고리 · 컬러웨이 · 사이즈표 |

사이드바 메뉴에는 **처리 대기 건수 배지**가 붙는다(승인 대기 바이어, 미확정 주문, 미답변 문의).
좁은 화면에서는 사이드바가 가로 스크롤 탭 스트립으로 바뀐다.

### Overview — "오늘 뭐 해야 하죠"에 답한다

지표 타일 4개와 **할 일 목록**. 할 일 항목은 각각 *방치하면 무슨 일이 생기는지*를 함께 적는다.

```
● 2 buyers waiting for approval
  승인 전까지 가격도 볼 수 없고 발주도 못 합니다.              [ Open ]

○ 0 orders not confirmed yet
  Nothing to do here.
```

처리할 게 없으면 회색으로 내려앉고 "Nothing to do here"라고 명시한다.
빈 화면은 "할 일이 없는 것"과 "화면이 고장 난 것"을 구별해주지 않는다.

## 3. 상품 등록 — 체크리스트가 게이트다

등록 폼 우측에 **공개 조건 5개**가 실시간 체크리스트로 붙는다.

| 조건 | 왜 |
|---|---|
| 이름 | 모든 화면과 주문서에 인쇄 |
| MSRP > 0 | 도매가가 여기서 계산되므로 0이면 라인시트가 깨진다 |
| 컬러웨이 1개 이상 | 매트릭스에 열이 하나도 없게 된다 |
| 설명 40자 이상 | 바이어가 자기 채널에 그대로 옮겨 쓴다 |
| 드라이브 링크 | 없으면 Assets 버튼이 열 게 없다 |

- 하나라도 비면 **"Show this product on the site" 스위치가 잠긴다.** 눌러도 켜지지 않고 무엇이 남았는지 안내한다
- 미완성 상태로 **저장은 된다** — 숨김 초안으로 남고, Overview의 할 일에 잡힌다
- 타이핑 중에는 체크리스트만 다시 그린다. 폼을 통째로 다시 그리면 **커서가 단어 중간에서 날아간다**

재고는 사이즈 × 컬러 표에 직접 입력한다. 0은 바이어 매트릭스에서 품절 처리되고, 초과 입력은
**차단이 아니라 앰버 경고** — 선주문 의사를 막지 않는다.

## 4. 콘솔에서 한 일이 사이트에 닿는 경로

프로토타입에서 실제로 검증된 왕복이다.

| 콘솔에서 | 사이트에서 |
|---|---|
| 홈 히어로 문구·브랜드 변경 → Publish | `#/` 첫 화면이 즉시 바뀐다 |
| 상품 등록 → 공개 스위치 ON | `#/shop`, 검색, 라인시트, 매트릭스에 동시 등장 |
| 공개 스위치 OFF | 매장 화면에서 사라진다. 과거 주문 기록은 그대로 |
| 대기 바이어 승인 | 그 계정으로 **로그인이 뚫린다** |
| 계정 정지 | 로그인 차단 + **접속 중이던 세션도 끊긴다** |
| 주문 상태 Shipped | 바이어 포털의 상태 배지가 바뀐다 |
| 문의 답변 | 바이어 포털 스레드에 그대로 도착한다 |

> 로그인 검증이 데모 계정 하드코딩에서 **계정 목록 조회**로 바뀌었다.
> 그래서 콘솔의 승인/정지가 실제로 의미를 갖는다.

## 5. 데모 계정

```
스태프 콘솔   admin@puppia.com / puppia-admin      (#/admin)
바이어 포털   buyer@demo-partner.com / puppia2026   (사이트 헤더의 Partner)
승인 대기     ana@petcasa.es / petcasa26            (승인 전에는 로그인 불가)
```

콘솔에 바이어 계정으로 로그인하려 하면 *"That is a **buyer** account. Buyers sign in on the storefront, not here."*
라고 응답한다. "비밀번호가 틀렸습니다"보다 훨씬 빨리 해결된다.

## 6. 실 구축 시 반드시 다르게 해야 하는 것

프로토타입은 `localStorage`(`puppia.admin.v1`)에 상태를 담는다. 동작을 보여주기 위한 것이지 권장 구현이 아니다.

| 항목 | 실 구축 |
|---|---|
| 인증 | HttpOnly 세션 쿠키 + 서버 검증. 스태프 계정은 2단계 인증 |
| 권한 | **역할 분리.** 상품은 고치되 바이어 승인은 못 하는 MD, 그 반대인 영업 |
| 저장 | MariaDB. 카페24 웹호스팅의 PHP 8.x + MariaDB 10.x 조합 |
| 이미지 | 업로드 후 리사이즈. 단, **대용량 자산은 드라이브 링크 유지** — 400MB 사진 묶음을 웹호스팅 대역폭으로 내보내면 트래픽이 먼저 죽는다 |
| 이력 | 누가 언제 무엇을 바꿨는지 감사 로그. 홈 배너는 되돌리기 대상이 될 일이 반드시 생긴다 |
| 삭제 | 소프트 삭제. 과거 주문이 참조하는 상품 레코드는 물리 삭제하면 안 된다 |
