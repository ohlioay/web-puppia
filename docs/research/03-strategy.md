# 03. 조합 전략 — 레퍼런스를 퍼피아에 어떻게 이식할 것인가

## 1. 한 문장 전략

> **"퍼피아 사이트는 쇼핑몰이 아니라 소프트하네스의 박물관이자, 바이어의 사무실이다."**

- 앞쪽(`/`)은 **애플 × 아크테릭스** — 제품을 해부해서 전문성을 증명하는 몰입형 쇼룸
- 뒤쪽(`/partners`) 은 **Faire × NuORDER** — 밀도 높고 빠른 업무 도구
- 둘을 잇는 접착제는 **동일한 타이포·컬러·형태 모티프**

## 2. 정보구조 (IA)

```
/                          홈 — 스크롤 서사 (아래 3장 참조)
│
├─ /soft-harness           ★ 시그니처 페이지 (홈 다음의 최중요 페이지)
│   ├─ /anatomy            해부: 원단 · 패턴 · 압력 분산 · 버클  [3D + 스크롤 시퀀스]
│   ├─ /series             A / B / C 계보도 + 컬러웨이 컨피규레이터
│   ├─ /fit                핏 파인더 (견종·치수 기반 사이즈 추천) [킬러 기능]
│   └─ /archive            세대별 개량 히스토리 타임라인
│
├─ /products               전체 카탈로그 (하네스 / 리드 / 의류 / 액세서리)
│   └─ /products/{sku}     제품 상세 — 360 뷰어 · AR · 사이즈표 · 실착 갤러리
│
├─ /new                    신상 / 시즌 컬렉션 (시즌마다 캠페인 필름 교체)
│
├─ /technology             PUPPIA SoftMesh™ 등 자체 기술·소재 페이지
│
├─ /stories                룩북 · 캠페인 · 브랜드 저널 (에디토리얼, 모션 최소)
│
├─ /about                  브랜드 · 제조 역량 · 지속가능성 (정적, 절제)
│
├─ /where-to-buy           국가별 공식 딜러 · 온라인 채널 맵
│
├─ /support                CS · FAQ · 사이즈 가이드 · 티켓 조회
│
└─ /partners               ■ B2B 존 (승인 로그인)
    ├─ /apply              바이어 신청 (공개)
    ├─ /catalog            디지털 라인시트 + 매트릭스 주문 그리드
    ├─ /orders             주문 이력 · 상태 추적 · 재주문
    ├─ /assets             브랜드 자산 다운로드 센터
    └─ /messages           문의 스레드
```

**의도적 설계 포인트**
- `/soft-harness` 를 `/products` 하위가 아니라 **최상위**에 둔다. URL 구조 자체가 "이게 우리의 아이폰"이라고 말한다.
- `/partners` 는 글로벌 내비게이션 **맨 오른쪽에 항상 노출**. 바이어가 헤매지 않게. 동시에 일반 소비자에겐 "이 브랜드는 전 세계에 유통한다"는 신호가 된다.

## 3. 홈 스크롤 시나리오 (씬 설계)

Mana Yerba Maté의 "제품이 스크롤 내내 화면을 떠나지 않는" 구조 + Apple의 씬 분할을 결합.

| 씬 | 화면 | 카피 (명사구) | 인터랙션 | 폴백 |
|---|---|---|---|---|
| **0. 로드** | 오프화이트 배경, 로고 + 형태 모티프 라인 드로잉 | — | 자산 프리로드 진행률 | 300ms 내 완료 시 스킵 |
| **1. 히어로** | 소프트하네스 3D가 천천히 회전. 배경 무지 | `SOFT HARNESS.` `SINCE 2002.` (실제 연도로 교체) | 커서 추적으로 미세 회전 | **정적 WebP 히어로 이미지** (LCP 요소는 이것) |
| **2. 왜 하네스인가** | 목줄 vs 하네스 압력 히트맵 비교 | `NECK. NO MORE.` | 스크롤에 따라 히트맵 색 전환 | 정적 비교 이미지 2장 |
| **3. 해부** | 하네스가 레이어별로 분해 | `FOUR LAYERS. ONE FIT.` | 스크롤 = 분해 진행률 (이미지 시퀀스) | 분해 스틸 4컷 그리드 |
| **4. 컬러웨이** | 시즌 컬러 스와치 그리드 | `THE PALETTE.` | 스와치 클릭 → 제품 컬러 실시간 변경 | 컬러별 정적 이미지 |
| **5. 실착** | 견종별 실착 화보 가로 스크롤 | `EVERY BODY.` | 드래그 가로 스크롤 + 견종 필터 | 세로 그리드 |
| **6. 핏 파인더 진입** | 큼직한 CTA 블록 | `FIND THE FIT.` | 인라인 미니 퀴즈 1문항 → 전체 퀴즈로 | 링크 버튼 |
| **7. 신상 / 시즌** | 캠페인 필름 (muted autoplay) | 시즌 카피 | 클릭 시 사운드 ON 전체화면 | 포스터 스틸 |
| **8. 글로벌 / 바이어** | 세계 지도 위 유통 국가 도트 | `IN N COUNTRIES.` | 도트 호버 → 국가명 | 정적 지도 이미지 |
| **9. 푸터** | 뉴스레터 · 소셜 · `PARTNER LOGIN` | — | — | — |

**규칙**
- 씬 1~4만 모션 예산을 쓴다. 5~9는 페이드/슬라이드 수준.
- 각 씬은 **독립 앵커 URL**을 가진다(`/#anatomy`) → 공유·광고 랜딩 가능.
- 전체 스크롤 길이는 데스크톱 기준 **7~9 화면**을 넘기지 않는다. 그 이상은 이탈한다.

## 4. 소프트하네스를 "아이폰화"하는 3단계

| 단계 | 이름 | 내용 | 근거 레퍼런스 |
|---|---|---|---|
| 1 | **Origin** | 왜 만들었는가. 목줄의 기관 압박 문제 → 소프트하네스의 발명. 창업 서사 | Arc'teryx, Rimowa |
| 2 | **Anatomy** | 무엇으로 되어 있는가. 원단 네이밍, 압력 분산 구조, 봉제 스펙, 3D 해부 | Apple, On, Arc'teryx |
| 3 | **Series** | 어떻게 진화했는가. 세대·모델 계보도, 컬러웨이 아카이브 | Nike Air Max, Kånken, Aeron |

이 3단계가 갖춰지면 신상은 "새 제품"이 아니라 **"계보에 추가된 다음 세대"** 로 읽힌다. 이것이 전문성의 실체다.

## 5. 기술 스택 (카페24 제약 반영)

```
프론트엔드 (정적 빌드 → 카페24 업로드)
  Astro 또는 Vite + TypeScript          ← HTML을 미리 생성 (SEO 확보, Node 런타임 불필요)
  GSAP + ScrollTrigger                  ← 스크롤 시퀀스 / 키네틱 타이포
  Lenis                                 ← 부드러운 스크롤 (reduced-motion 시 비활성)
  Three.js (필요 지점만 동적 import)     ← 히어로 1개 + 컨피규레이터 1개, 그 이상 금지
  <model-viewer>                        ← 제품 상세 AR (iOS USDZ / Android Scene Viewer)
  Swiper / 순수 CSS scroll-snap         ← 갤러리

백엔드 (카페24 웹호스팅)
  PHP 8.x + MariaDB 10.x
  ├─ 세션 기반 바이어 인증 (승인제)
  ├─ 문의 티켓 CRUD + 상태 조회
  ├─ 주문서(매트릭스 그리드) 저장 → PDF/XLS 생성
  ├─ 자산 다운로드 서명 URL + 로그
  └─ 관리자 백오피스 (바이어 승인, 가격표, 재고 업로드 — CSV 임포트로 충분)

인프라
  Cloudflare (무료)     ← SSL, 글로벌 CDN, 캐싱. 카페24 트래픽 비용 방어
  Cloudflare R2 / S3    ← .glb, 영상, 고해상 화보, 바이어 자산 zip
  GitHub Actions        ← 빌드 후 SSH/FTP로 카페24 배포 자동화
```

**하지 말아야 할 것**
- 카페24 Node.js 호스팅 사용 (Node 14 + SSL 미지원)
- Next.js SSR을 카페24에 올리려는 시도
- 3D 씬을 3개 이상 만드는 것 (제작비·유지보수·성능이 모두 3배)
- 3D 모델을 카페24에서 직접 서빙 (트래픽 종량 과금)

## 6. 단계별 로드맵

### Phase 1 — 브랜드 각인 (약 8~10주)
- 홈 스크롤 서사 (씬 1~9, 3D는 히어로 1개만)
- `/soft-harness` Origin + Anatomy (이미지 시퀀스 기반, 3D 아님)
- `/products` 카탈로그 + 제품 상세
- `/about`, `/stories`, `/support`, `/where-to-buy`
- 문의 티켓 시스템 (4갈래 라우팅)
- EN/KO 2개 언어
- **Phase 1 완료 시점에 "전문 브랜드로 보이는가"가 판가름 난다. 여기에 예산을 몰아야 한다.**

### Phase 2 — 바이어 운영 (약 6~8주)
- `/partners` 승인 로그인
- 디지털 라인시트 + 매트릭스 주문 그리드
- 거래처별 차등 가격 · 실시간 재고 · MOQ/인코텀즈
- 브랜드 자산 다운로드 센터
- 주문 이력 · 재주문 · 포털 메시지 스레드
- 관리자 백오피스

### Phase 3 — 차별화 기능 (약 6주)
- 핏 파인더 (견종 프리셋 DB)
- 컬러웨이 3D 컨피규레이터
- 제품 상세 AR
- `/soft-harness/archive` 타임라인
- 실착 UGC 갤러리
- 언어 3~5개로 확장
